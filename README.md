# StockFit

투자성향과 종목의 적합도를 DART 공시 재무데이터로 분석하는 초보자용 웹 서비스 (v0.1, 시연용)

## 실행 방법 (Windows)

1. Node.js 24가 필요해요. PowerShell에서 `node -v`로 확인하세요.
2. 이 폴더에서 `.env.example`을 복사해 `.env`로 이름을 바꾸고, 가진 키를 붙여넣으세요.
3. 이 폴더에서 PowerShell을 열고 처음 한 번 설치한 뒤 실행하세요.
   ```
   npm install
   npm start
   ```
4. 브라우저에서 http://localhost:3000 을 여세요.

외부 라이브러리는 배포용 Postgres 연결에 쓰는 `pg` 하나뿐이에요. `DATABASE_URL`이 없으면 내 컴퓨터의 `data/stockfit.db`(SQLite)를 써서 별도 설정 없이 개발할 수 있어요.

처음 실행하면 DART에서 상장사 고유번호 목록을 받아 `data/corp-codes.json`에 저장해요(하루 한 번 갱신).
터미널에 `상장사 N개 준비 완료`가 뜨면 상장사 전체를 이름이나 종목코드로 검색할 수 있어요.
`.env`에 키가 없으면 예시(가상) 데이터로 삼성전자, SK하이닉스, 현대자동차 3종목만 동작해요.

## 배포 (GitHub → Neon → Render)

Render 무료 플랜은 서버 파일이 재시작·재배포·잠들 때마다 지워져요. 그래서 회원 정보는 외부 Postgres(Neon)에 저장해요.

1. **GitHub에 올리기**
   ```
   git init
   git add .
   git status
   ```
   `git status` 목록에 `.env`, `data/`, `node_modules/`가 **없는지** 확인한 뒤 커밋하고 GitHub 저장소에 올려요.
2. **Neon에서 DB 만들기**: neon.com 가입 → 프로젝트 만들기 → **Connection string** 복사 (`postgresql://...` 형태). 테이블은 서버가 처음 켜질 때 자동으로 만들어요.
3. **Render에서 Web Service 만들기**: GitHub 저장소 연결
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Node 버전은 `.node-version`(24)과 `package.json`의 `engines`로 정해져요.
4. **Render Environment에 넣을 값**
   - `DATABASE_URL`: Neon에서 복사한 주소 (**필수**, 없으면 회원 정보가 계속 사라져요)
   - `APP_URL`: `https://내서비스.onrender.com`
   - 가진 키들: `DART_API_KEY`, `DATA_GO_KR_KEY`, `ECOS_API_KEY`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `OPENAI_API_KEY`
   - 선택: `OPENAI_MODEL`, `CHAT_DAILY_LIMIT`
   - `PORT`는 넣지 마세요. Render가 알아서 정해요.
5. 배포 로그에 `DB: Postgres (...)`가 보이면 연결된 거예요.

알아둘 점
- 무료 플랜은 15분 동안 방문이 없으면 잠들고, 다음 첫 접속은 1분쯤 걸려요.
- 업종 비교 데이터는 DB에 저장돼서 재시작해도 남아요. 처음 한 번 모을 때 10분 넘게 걸리고, 잠들면 중간에 멈췄다가 다음에 이어서 받아요.
- 로그인 쿠키는 HTTPS 접속에서 `Secure`로 설정돼요.
- 공공데이터포털 시세는 상업적 이용이 금지라 시연·학습용으로 써요. 일반에 공개해서 회원을 받는다면 개인정보처리방침 페이지도 필요해요.
- DB 연결에서 인증서 오류가 나면 `DATABASE_SSL=no-verify`를 추가해요 (Neon은 보통 필요 없어요).

## 내 성향에 맞는 종목

검색창 아래에 내 성향 기준 적합도가 높은 종목 5개를 보여줘요.

- 후보: 시세 키가 있으면 **시가총액 상위 50개**(우선주·ETF 제외), 없으면 주요 대형주 목록, DART 키도 없으면 예시 종목
- 서버가 후보들의 재무·주가 데이터를 미리 모아두고(하루 한 번 갱신), 접속한 사람의 성향으로 적합도만 다시 계산해요. 성향을 바꾸면 바로 바뀌어요.
- 업종 비교 데이터가 준비된 뒤에 모아서, 종목 화면과 같은 점수가 나와요. 준비되기 전에는 예시 종목을 보여줘요.
- "투자 추천이 아니라 후보 안에서 내 기준에 더 가까운 순서"라는 안내를 함께 보여줘요.
- 모은 데이터는 DB(`api_cache`)에도 저장해서 서버가 잠들었다 깨어나도 다시 받지 않아요 (DART 3일, 주가 6시간).
- API: `GET /api/picks?q1=...&q7=...`

## 초보자 모드 / 전문가 모드

상단 메뉴의 `초보자 | 전문가`로 바꿔요. 고른 모드는 이 기기에 기억해요. 고른 적이 없으면 설문의 금융 지식 답으로 정해요("대부분 이해해요" 이상이면 전문가, 아니면 초보자).

| | 초보자 | 전문가 |
|---|---|---|
| 결과 첫 화면 | "처음이라면 이렇게 보세요" 안내 | 없음 |
| 적합도 패널 | 내 성향과 **맞는 점 / 조심할 점** (쉬운 문장) | 기준 점수 × 비중 계산 내역, 위험 조정, 금리·위험 등급 |
| 기업 상태 설명 | 쉬운 해석 + 업종 비교 문장 | + 점수 기준표 |
| 숫자로 자세히 보기 | 숨김 | 모든 지표와 평가 근거 |
| 계산 방법 안내 | 쉬운 설명 | 기준표 전체, 데이터 연결 상태 |

화면 요소에 `beginner-only` / `expert-only` 클래스를 붙이면 해당 모드에서만 보여요.

## AI 도우미

- `.env`에 `OPENAI_API_KEY`를 넣으면 오른쪽 아래에 버튼이 생겨요. 모델은 `OPENAI_MODEL`(기본 `gpt-4o-mini`)로 바꿀 수 있어요.
- **로그인한 회원만** 쓸 수 있어요. 로그인 전에 질문을 누르면 로그인 안내가 뜨고, 로그인하면 그 질문을 이어서 물어봐요.
- 지금 보고 있는 종목의 분석 결과(적합도, 기준별 점수, 지표, 위험 등급, 금리)를 **서버가 직접 계산해서** 함께 보내요. 화면에서 보낸 숫자는 쓰지 않아요.
- 지시문으로 **매수·매도 권유, 목표 주가, 주가 예측을 하지 않게** 하고, 데이터에 없는 사실은 지어내지 않게 해요. 예시 데이터일 때는 가상 수치라고 알려줘요.
- 비용 관리: 질문 500자, 최근 대화 12개, 답변 최대 600토큰, 한 계정 10분에 20번, 사이트 전체 하루 `CHAT_DAILY_LIMIT`번(기본 300).
- 대화 기록은 브라우저 탭을 닫으면 사라지고(sessionStorage), 로그아웃하면 지워져요.
- 기업 상태 설명의 "이 부분 AI 도우미에게 물어보기"와 추천 질문을 누르면 바로 질문해요.
- API: `POST /api/chat` `{ messages, code, profile, mode }` → `{ reply }`

## 뉴스·공시

- 종목 화면의 "최근 뉴스·공시" 카드: 그 종목의 최신 뉴스 5개 또는 최근 3개월 공시 5개
- 관심종목 아래 "관심종목 소식": 찜한 종목 전체의 뉴스와 공시를 최신순으로 (전체 / 뉴스 / 공시 / 중요 공시만)
- 공시는 종류별로 쉬운 설명을 붙이고, 주주에게 영향이 큰 공시는 `중요`, 횡령·상장폐지 같은 공시는 `주의`로 표시해요.
- 공시는 DART 키, 뉴스는 네이버 검색 API 키(`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`)가 필요해요. 없으면 그 부분만 빼고 안내 문구를 보여줘요.
- 같은 종목은 15분 동안 다시 조회하지 않아요.
- 소식 API: `GET /api/feed?codes=005930,000660` (최대 20종목)

## 사용한 DART API

- `fnlttSinglAcnt` 단일회사 주요계정(3년치): 자산·부채·자본, 매출액, 영업이익, 당기순이익 등
- `fnlttSinglAcntAll` 단일회사 전체 재무제표: 매출총이익, 영업활동현금흐름, 이자 지급액
- `fnlttMultiAcnt` 다중회사 주요계정: 업종 비교용 (100개씩)
- `alotMatter` 배당에 관한 사항(3년치): 주당 배당금, 현금배당수익률, 현금배당성향
- `corpCode` 고유번호 목록: 상장사 전체의 종목코드 ↔ 고유번호
- `company` 기업개황: 시장 구분, 업종 코드
- `list` 공시검색: 종목별 최근 공시 목록

## 적합도 계산 (v1)

수익률 예측이 아니라 **재무 건전성과 위험 수준이 내 성향과 맞는지**를 봐요.

1. 설문 7문항(`public/survey.js`) → 5단계 투자성향. 투자자정보확인서 항목(나이, 투자 기간, 투자 경험, 금융 지식, 자산 중 투자 비중, 손실 감내도)과 선호 기업 유형의 점수 합계를 5구간으로 나눠요.
   - "원금 손실은 싫어요"를 고르면 다른 답과 상관없이 안정형이에요.
   - 예전 3문항 답변만 있으면 예전 방식으로 계산하고 "간이"로 표시해요. 설문을 다시 하면 7문항으로 바뀌어요.
2. 선호 기업·투자 기간·손실 감내도에 따라 6개 기준의 비중을 정해요. 국고채 3년 금리가 3.5% 이상이면 안정성 비중을 20% 높여요.
3. 지표마다 0~100점을 매겨요. 같은 업종(KSIC 앞 2자리) 회사가 8곳 이상 모였으면 **업종 안 순위**, 아니면 고정 기준표(`src/scoring.js`의 `METRICS`)를 써요.
4. 기준 점수(지표 평균) × 비중을 모두 더한 값이 적합도예요. 데이터가 없는 기준은 빼고 비중을 다시 맞춰요.
5. 최근 3년 주가로 위험 등급(97.5% VaR, 1~6등급)을 매겨서 **안내로만** 보여줘요. 펀드 기준 구간이라 개별 주식은 거의 다 1~2등급이어서, 점수에서 깎으면 안정형에게 모든 종목이 낮아져 비교가 안 되기 때문이에요. 주가 변동은 "주가 안정성" 기준으로 점수에 반영돼요.
6. 안정형·안정추구형에게는 "주식은 원금 손실이 생길 수 있는 상품이고, 점수는 주식들 사이의 비교"라는 안내를 적합도 패널 맨 위에 항상 보여줘요.

| 기준 | 지표 | 근거 | 필요한 키 |
|---|---|---|---|
| 안정성 | 부채비율, 유동비율, 이자보상배율, Altman Z″ | 부실예측 모형(Altman 1995, 비제조업·신흥시장용) | DART |
| 수익성 | 영업이익률, ROE, 총자산 대비 매출총이익, 발생액 비율 | Novy-Marx(2013), 코스피 실증(Yoon & Liu 2015), 이익의 질(Sloan) | DART |
| 성장성 | 1년·3년 매출 성장률, 성장의 꾸준함 | 1년치는 우연이 커서 3년 추세 함께 | DART |
| 배당 | 배당수익률, 국고채 금리와의 차이, 배당성향 구간, 연속 배당 | 배당성향이 높을수록 배당 삭감이 잦음(Morningstar, CFA) | DART (+ECOS) |
| 가격 수준 | PER, PBR | 업종 안 비교 | DART + 시세 |
| 주가 안정성 | 연 변동성, 1년 최대 하락폭 | 한국 시장 저변동성 이상현상 연구 | 시세 |

재무 체크리스트는 피오트로스키 F-score 9개 항목을 쉬운 문장으로 보여줘요. 점수에는 넣지 않고 참고용이에요.

### 키를 넣으면 바로 동작해요

`.env`에 키를 넣고 서버를 다시 켜면 돼요. 없는 키는 그 부분만 빼고 계산하고, 화면 아래 "적합도는 어떻게 계산하나요? → 데이터 연결 상태"에서 확인할 수 있어요.

| `.env` 항목 | 발급처 | 없으면 |
|---|---|---|
| `DART_API_KEY` | opendart.fss.or.kr | 예시 3종목만 |

- 분석 API 응답에는 `checklist`, `price`, `macro`, `sources`, `fit.risk`, `fit.warnings`가 함께 와요. 연결 상태는 `GET /api/status`.

## 회원 기능

- 이메일·비밀번호·닉네임으로 가입하고, 로그인하면 투자성향과 관심종목이 계정에 저장돼요.
- 로그인하기 전에 이 기기에서 저장한 관심종목은 계정 데이터와 합쳐져요. 투자성향은 계정에 저장된 것이 우선이에요.
- 로그아웃하면 이 기기에 남아 있던 성향과 관심종목도 지워요.
- 데이터는 `DATABASE_URL`이 있으면 그 Postgres에, 없으면 Node.js 내장 SQLite `data/stockfit.db`에 저장돼요. 두 곳의 테이블 구조는 같아요.
  - `users`: 이메일, 닉네임, 비밀번호 해시, 투자성향, 가입일, 마지막 로그인
  - `sessions`: 로그인 상태 (토큰 해시, 만료 시각)
  - `watchlist`: 회원별 관심종목
  - `email_tokens`: 이메일 인증·비밀번호 재설정 링크용 일회용 토큰
- 백업은 서버를 끈 상태에서 `data/stockfit.db` 파일을 복사하면 돼요.

### 이메일 인증, 비밀번호 찾기

- 가입하면 인증 메일이 가요(링크 24시간 유효). 인증 전에도 로그인은 되지만 화면 위에 인증 안내와 재발송 버튼이 보여요.
- 로그인 창의 "비밀번호를 잊으셨나요?"에서 이메일을 입력하면 재설정 링크가 가요(30분 유효, 한 번만 사용).
  가입하지 않은 이메일이어도 같은 안내가 떠서 가입 여부를 알 수 없어요.
- 비밀번호를 바꾸면 모든 기기에서 로그아웃되고, 바꾼 브라우저에서는 바로 로그인돼요.
- 같은 메일은 1분에 한 번만 보내요.

**메일 설정** (`.env`, 항목은 `.env.example` 참고)

- 설정이 없으면 **이메일 인증과 비밀번호 찾기는 꺼지고**(화면에서도 숨김) 가입·로그인만 동작해요. 인증하지 않아도 모든 기능을 쓸 수 있어요.
- SMTP 설정을 넣고 서버를 다시 켜면 두 기능이 켜져요.
- Gmail로 보내려면:
  1. 구글 계정에서 2단계 인증을 켜요.
  2. "앱 비밀번호"를 만들어요.
  3. `.env`에 `SMTP_HOST=smtp.gmail.com`, `SMTP_USER=내 Gmail 주소`, `SMTP_PASS=앱 비밀번호 16자리`를 넣어요.
- 네이버로 보내려면:
  1. 네이버 메일 환경설정에서 POP3/SMTP 사용을 켜요.
  2. `SMTP_HOST=smtp.naver.com`을 넣고, `SMTP_USER`와 `SMTP_PASS`를 채워요.
- 실제 도메인으로 공개할 때는 `APP_URL`을 그 주소로 바꿔야 메일 속 링크가 맞게 만들어져요.
- 비밀번호는 scrypt 해시로만 저장하고, 세션은 HttpOnly 쿠키로 30일 유지돼요.
- 같은 이메일로 5번 연속 틀리면 5분 동안 로그인을 막아요.
- 회원 API: `POST /api/auth/signup`, `/login`, `/logout`, `/verify`, `/resend-verify`, `/forgot`, `/reset`, `GET·PUT /api/me`

실제 서비스로 공개할 때는 HTTPS를 적용하고 쿠키에 `Secure`를 붙이세요.
